# نقطة بيع للمطاعم · مربوطة بمنصة فاتورة

كاشير مطاعم سحابي جاهز للتشغيل — طلبات **صالة / سفري / توصيل**، خريطة طاولات، شاشة مطبخ (KDS)، ورديات وإغلاق نقدي (X/Z)، تقارير مبيعات، وإدارة كاملة للقائمة — مع **فوترة إلكترونية متوافقة مع هيئة الزكاة والضريبة (ZATCA)** و**الدفع الإلكتروني عبر منصة فاتورة (Fatora.io)**.

بُني بنفس معمارية نظام «إدارة وإغلاق فروع المطاعم» ليكمّله: نفس طبقة التخزين السحابي (Firestore ← خادم ← محلي)، ونفس أسلوب الفواتير ورمز ZATCA، وواجهة عربية RTL بوضعين فاتح/داكن.

---

## ⚡ التشغيل السريع

```bash
npm install
cp .env.example .env      # اختياري: لتفعيل الدفع عبر فاتورة و/أو Firestore
npm run dev               # الخادم + واجهة التطوير معاً → http://localhost:3000
```

### البناء والإنتاج

```bash
npm run build             # يبني الواجهة في dist/
npm start                 # يشغّل الخادم ويخدم dist → http://localhost:8787
```

### حسابات الدخول التجريبية (رمز PIN)

| المستخدم | الدور | الرمز |
|---|---|---|
| المدير | مدير النظام (كل الصلاحيات) | `1234` |
| الكاشير | كاشير (بيع فقط) | `1111` |

غيّرها فوراً من **الإدارة ← المستخدمون** قبل التشغيل الفعلي. تُنشأ القائمة والطاولات التجريبية تلقائياً عند أول تشغيل.

## 🧩 الوحدات

- **البيع** — شبكة أقسام وأصناف كبيرة اللمس، سلة حية، إضافات/أحجام/ملاحظات، خصم، وأنواع طلب (صالة/سفري/توصيل).
- **الطاولات** — خريطة الصالة بمناطقها؛ الطاولة المشغولة تعرض المبلغ والمدة؛ لمسة تفتح طلبها.
- **الطلبات** — النشطة والمعلّقة والمدفوعة والملغاة، بحث سريع، إعادة طباعة، واسترجاع.
- **المطبخ (KDS)** — تذاكر حسب المحطة، تقادم لوني، تعليم «جاهز»، وإعادة طباعة KOT.
- **الوردية** — فتح بعهدة، حركات درج (إيداع/صرف)، تقرير X فوري، وإغلاق Z بعدّ نقدي وفروقات.
- **التقارير** — مبيعات اليوم، حسب الساعة والقسم، أعلى الأصناف، توزيع وسائل الدفع، وتصدير CSV.
- **الإدارة** — القائمة (أقسام/أصناف/إضافات)، الطاولات، المستخدمون والأدوار، بيانات المنشأة والضريبة، إعداد فاتورة، والمظهر.

## 💳 الربط مع منصة فاتورة (Fatora.io)

### مبدأ الأمان
**مفتاح التاجر السرّي لا يصل المتصفح إطلاقاً.** كل نداءات فاتورة تمرّ عبر وسيط الخادم (`server.js`) الذي يضيف المفتاح من متغيّر البيئة `FATORA_API_KEY`.

### الإعداد
1. احصل على **مفتاح API** من لوحة تحكم فاتورة.
2. في `.env`:
   ```
   FATORA_API_KEY=مفتاحك_السري
   FATORA_BASE_URL=https://api.fatora.io/v1
   PUBLIC_BASE_URL=https://عنوان-تطبيقك.العام
   ```
   `PUBLIC_BASE_URL` مهم: منه تُبنى روابط العودة التي تعيد إليها فاتورة العميل بعد الدفع.
3. من **الإدارة ← الإعدادات ← الربط مع منصة فاتورة**: فعّل الدفع، واختر الطريقة واللغة والعملة. يظهر مؤشّر أخضر عندما يكتشف التطبيق أن الخادم يملك المفتاح.

### التدفّق
```
الكاشير يختار «فاتورة» في شاشة الدفع
   → الخادم ينشئ عملية دفع (POST /v1/payments/checkout) ويعيد checkout_url
   → (أ) تحويل الجهاز لصفحة الدفع، أو (ب) عرض رمز QR ليدفع العميل من جواله
   → بعد الدفع تعيد فاتورة العميل مع: order_id · transaction_id · payment_id · response_code
   → الخادم/التطبيق يتحقّق (POST /v1/payments/verify) قبل اعتماد الفاتورة
   → عند التأكيد: تُسجَّل الدفعة، تُغلق الفاتورة، ويُطبع الإيصال (مع رمز ZATCA)
```
- **مانع التكرار:** لكل محاولة دفع `order_id` فريد؛ ولا تُعتمد فاتورة إلا بعد تحقّق `verify`.
- **الوضعان:** `redirect` (تحويل جهاز الكاشير) و`link` (رمز/رابط للعميل مع استطلاع تلقائي للتأكيد ومهلة دقيقتين).
- **الدفع المختلط/المقسّم:** يمكن جمع نقد + شبكة + فاتورة على فاتورة واحدة حتى يُسدَّد المتبقّي.

> ملاحظة: بنية استجابة `verify` قد تختلف بين حسابات فاتورة؛ الوسيط يستنتج «مدفوعة» بمرونة (كلمات النجاح ورمز الاستجابة). راجع حساب فاتورة لديك واضبط `inferPaid` في `server.js` إن لزم.

## 🧾 الفوترة الإلكترونية (ZATCA)

يُطبع على كل فاتورة بيع رمز **QR متوافق مع المرحلة الأولى من فاتورة ZATCA** (ترميز TLV/Base64: اسم البائع، الرقم الضريبي، الوقت، الإجمالي، الضريبة) — **فقط** عندما يكون البائع مسجّلاً ضريبياً (رقم ضريبي مضبوط ونسبة ضريبة > 0). مع عملة/نسبة صفرية (مثل السوق القطري) لا يُطبع الرمز لأنه بلا معنى.

- الأسعار **شاملة ضريبة القيمة المضافة**؛ الضريبة تُستخلص: `الضريبة = الإجمالي × النسبة ÷ (100 + النسبة)`.
- النسبة والعملة قابلتان للضبط من الإعدادات (افتراضياً 15% و«ر.س»).

## 🏗️ البنية

```
├── index.html        صفحة الجذر (RTL)
├── main.jsx          نقطة الدخول
├── App.jsx           الجذر: التحميل، الدخول، الهيكل، وشاشة البيع
├── screens.jsx       الطاولات، الطلبات، المطبخ، الورديات، التقارير، الإدارة، والدفع
├── ui.jsx            مكوّنات واجهة مشتركة (نافذة، حقل، شريط مقسّم…)
├── styles.js         نظام التصميم (وضعان + أربع هويّات لونية)
├── menu.js           نموذج المجال: حساب الطلب والضريبة + القائمة التأسيسية
├── invoice.js        العملة + رمز ZATCA QR + باني الإيصال الحراري وتذكرة المطبخ
├── fatora.js         عميل فاتورة (يتحدّث مع وسيط الخادم فقط)
├── storage.js        طبقة التخزين: Firestore ← خادم ← محلي
├── server.js         خادم Express: التخزين المشترك + وسيط فاتورة الآمن
└── firestore.rules   قواعد أمان Firestore
```

### المزامنة متعددة الأجهزة
كل الأجهزة تعمل على قاعدة واحدة. مع Firestore تكون المزامنة **لحظية** عبر `onSnapshot`؛ ومع خادم المشروع تُحدَّث كل 8 ثوانٍ؛ وعند انقطاع الشبكة يتحوّل التخزين تلقائياً إلى نسخة المتصفح المحلية فيبقى الكاشير يعمل. السلة قيد البناء محلية، ولا تُكتب في القاعدة المشتركة إلا عند الإرسال للمطبخ أو التعليق أو الدفع.

### تفعيل Firestore (موصى به للإنتاج)
املأ متغيّرات `VITE_FIREBASE_*` في `.env`، وفعّل **Firestore** و**Anonymous Authentication**، ثم ارفع القواعد:
```bash
firebase deploy --only firestore:rules
```

## 🚀 النشر

### خادم Node واحد (Render / Railway / Docker / VPS)
الخادم يخدم الواجهة المبنية ويؤمّن وسيط فاتورة معاً.
- **Render/Railway:** ملف `render.yaml` مرفق — البناء `npm install && npm run build`، التشغيل `node server.js`.
- **Docker:** `docker build -t rpos . && docker run -p 8787:8787 -e FATORA_API_KEY=... rpos`.
- اضبط `FATORA_API_KEY` و`PUBLIC_BASE_URL` في متغيّرات البيئة.

> تنبيه: استضافات السحابة تمسح نظام الملفات عند كل نشر، فيُفقد `data/store.json`. للإنتاج فعّل Firestore حتماً لتُحفظ البيانات.

### Firebase Hosting (للواجهة فقط)
`firebase.json` مرفق. الدفع عبر فاتورة يحتاج خادماً؛ انشر `server.js` كوظيفة (Cloud Function/Worker) ووجّه `/api` إليه.

## 🔐 ملاحظات أمنية

- مفتاح فاتورة خادمي فقط (`FATORA_API_KEY`) — لا يُخزَّن في الواجهة ولا في قاعدة البيانات.
- رموز دخول الكاشير (PIN) للتشغيل اليومي؛ للحماية الأعلى شدّد `firestore.rules` واربط الكتابة بأجهزة معتمدة.
- لا تُعتمد أي فاتورة مدفوعة عبر فاتورة إلا بعد تحقّق `verify` من الخادم.
